# 发布前审核清单

使用 PASS / WARN / FAIL，不用“看起来还行”代替证据。

| 类别 | 通过要求 |
|---|---|
| 采集完整度 | 对标标题、正文、图片与顺序已明确；缺项已公开说明 |
| 对标贴近度 | 结构、单图层级、篇幅、口语节奏、泛化视觉与对标相符，非未经要求另起炉灶 |
| 原创性 | 没有抄原句、原剧情、独特构图，没有搬运或去除水印 |
| 标题 | 20 字以内，具体、自然、不夸大 |
| 图文匹配 | 每张图表达一个明确观点，caption 与画面不矛盾；指出画面承担的信息及文字补充的信息，而非只检查主题一致 |
| 人物连续 | 多图人物外貌、服装、关系稳定；不出现明显身份漂移 |
| 视觉质量 | 手指、人体、透视、反射、文字/物件数量无明显异常 |
| 手机阅读 | 字号合适，对比清晰，安全留白；真实手机预览核查 |
| 结构 | 并列卡独立、故事因果连续、对照条件可比或教程步骤完整，按实际类型判断 |
| 约束与同步 | 分镜前已固定五项形式约束；整组提示词与当前JSON一致，完整文案无占位符 |
| 历史选题 | 已检查相近主题、场景和动作，明确本次区别；不将字面检索当语义判定 |
| 平台规范 | 发布内容与素材有合法使用权，不涉及未经授权的第三方作品 |
| 交付真实 | 提示词与实际带字图片严格区分；图片存在且经过审核才报告成品完成 |

## 逐图图文配合检查

分镜时在 `03-storyboard.md` 逐图记录，成图后在 `05-review.md` 核对实际结果：

| 卡片 | 具体处境 | 画面承担的信息 | 文字补充的信息 | 删掉画面的损失 | 结果与证据 |
|---|---|---|---|---|---|

检查动作、表情、道具是否让读者看见冲突或行动。比如“人物站着＋拒绝话术”通常只有装饰作用；展示排满的日程，可以让画面交代拒绝的处境，文字补充回应方式。此例仅用于解释检查方法，不要求每张都出现日程表。

删除画面后信息几乎不变是诊断信号，不是自动FAIL：话术卡可文字主导，画面提供情境、情绪或阅读节奏也成立。若整组都只有换姿势的人物和抽象道理，应先改进场景与动作；不以塞入道具、夸张表演或删掉长解释来应付检查。没有图片时仅评价分镜计划，实际图文配合写待评。

形式贴近与内容原创分别给结论与证据，不互相抵消；具体判断见 `analysis-rubric.md`。

审核过程应给出每一项结果与至少一处具体依据；有 WARN 写出人工复核动作；有 FAIL 则先修复再二审。代码脚本只检查结构/文件，不等同于视觉与原创性审核。
