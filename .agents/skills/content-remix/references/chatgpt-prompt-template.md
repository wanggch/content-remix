# 四种结构的提示词规则

先在 `cards.json` 选择 `content_structure`；脚本按结构添加对应组织规则，生成唯一的 `prompts/创作提示词.md`。完整数据格式见 `cards-schema.md`，不要再手工维护另一份模板成品。

| 类型 | 适用内容 | 分镜要求 | 场景连续性 |
|---|---|---|---|
| parallel 并列话术卡 | 多条建议、独立话术、并列情境 | 每张独立成立；保留各卡文字层级与解释量 | 人物和画风统一，时间地点可变 |
| story 连续故事 | 同一事件的变化与结果 | 开场、推进、转折、回应；图数由内容决定 | 时间、空间、道具和因果连续 |
| contrast 前后对照 | 两种做法、前后状态比较 | role标明对照组或配对；比较条件一致，不以无关变化制造效果 | 对应场景可比，人物与视觉尺度稳定 |
| tutorial 步骤教程 | 具体操作或行动顺序 | role标明步骤；scene写输入、动作、结果和必要依赖 | 工具与对象变化符合操作顺序 |

## 共用内容

完整总提示词包括：图片数量与独立输出要求、目标读者与核心表达、结构规则、人物、画风、场景规则、画幅、文字布局、逐图任务与画面、准确文案、质量要求、缺图续生成和误生成拼图时的处理说明。

总提示词必须自包含；不能依赖用户未上传的参考图、本地路径或其他文件。不要用概括替代准确文案。气泡＋解释卡保留两个文字区，不能把解释塞进气泡或自动缩为标语。

## 选择与覆盖

- 默认沿用对标内容结构；用户明确要求改结构时在约束中写明依据。
- 不把四图都写成起承转合：这只适用于连续故事。
- 人物一致不等于场景连续。并列卡可以跨时间地点，不要求建立因果。
- 素材不足时将对应约束标为unknown，说明当前结构是创作选择而非已观察事实。
- 图数与画幅可以覆盖默认值；脚本使用实际cards数量与aspect_ratio，不将非四张当错误。

## 生成与同步

```bash
python3 "$SKILL_DIR/scripts/build_prompt.py" --project "$PROJECT" --contract-only
python3 "$SKILL_DIR/scripts/build_prompt.py" --project "$PROJECT"
python3 "$SKILL_DIR/scripts/quality_check.py" --project "$PROJECT"
```

前一命令用于分镜前固定约束，后一生成命令用于完整交付。修改JSON后重新生成；脚本只整理数据，不负责选择主题、润色文案或判断审美。实际图片需核对中文、人物和手机可读性，不提供定向返修提示词。
