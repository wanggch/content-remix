# 创作质量评估

## 固定案例的定位

`evals/cases.json` 保存四种结构的合成回归案例及预期检查点；它们用于验证流程规则，均未获用户作品认可。不能据此声称文案质量、审美或发布表现已经得到用户验证。

```bash
python3 "$SKILL_DIR/scripts/evaluate.py" --out "$WORKSPACE/creative-evaluation.md"
```

脚本运行固定数据，验证结构路由、单文件交付、准确文案保留和角色/场景规则，并生成报告。报告把程序性检查和待语义检查分别列出。本轮代理的文本语义审查单独保存在 `evals/semantic-review.md`，修改案例后应重新审查并更新该记录。失败时不更新Skill安装副本，先修复再验证。

## 语义审查

修改Skill或增加认可案例时，实际阅读全文和必要图片，按以下维度给PASS/WARN/FAIL并引用具体卡片与短句：

| 维度 | 判断问题 |
|---|---|
| 选题贴近 | 目标读者、表达主体和核心任务是否保留？标题承诺是否相近？去掉标题是否仍解决同一具体问题？改变时是否有用户依据？ |
| 对标形式 | 内容结构、信息层级、阅读量、泛化视觉是否符合约束？ |
| 生活语感 | 台词在该场景中能自然说出口吗？是否空泛、说教或不合角色？ |
| 可视化 | scene能形成明确动作与构图吗？是否靠抽象文字才能理解？ |
| 图文配合 | 文案和画面各提供信息，是否出现矛盾或机械重复？ |
| 结构完整 | 并列是否独立，对照是否可比，故事是否因果连贯，教程是否缺关键步骤？ |
| 原创表达 | 是否复用可识别原句、独特角色、情节或构图？历史主题与动作是否重复？ |

没有对标或实际生成图的维度写待评，不凭程序通过标PASS。记录与上版相比的具体退步，不能只给一个总分。

## 真实案例库（工作区，不随Skill分发）

在 `$WORKSPACE/.content-remix/cases/<案例名>/case.md` 保存真实案例，初期积累3～5组。创作前按主题、结构、问题类型读取相关案例，不强制读取整个库。无需改动 `创作资料/cards.json` schema 或历史检索脚本；案例检索与判断由代理完成。

每个案例按以下模板记录：

```markdown
# 案例名称
- 项目路径：
- 状态：observed / feedback_received / user_approved
- 主题、结构、问题类型：未知时明确注明
## 输入与对标
素材位置、用户任务原话；缺失项写待补，不复制整篇第三方素材。
## 初稿
首次实际保存的版本位置与必要片段；没有历史版本写未保存。
## 用户反馈
原话、来源位置、针对的卡片或维度；代理诊断单独标注。
## 修改后
实际修改版本位置、必要前后对照和修改原因；未发生写待补。
## 认可范围
明确认可的维度、原话与证据；未认可的部分、适用条件和未知项。
## 可复用规则
从具体反馈提炼的有限规则；无证据时写暂无，不将一次题材选择泛化。
## 发布观察
引用项目记录/发布数据.md；发布时刻、数据截止时刻、阅读与互动数据、来源和缺项。
```

收到反馈时保存用户原话、修改摘要、认可范围和当前文件引用，不默认复制图片或保存JSON快照。已删除的过程作品不恢复，无法复核的旧版本明确标为仅有摘要。没有修改或认可也可以建观察案例，不制造前后对照。

状态含义：`observed` 只有真实任务或发布观察；`feedback_received` 有针对作品的实际反馈；`user_approved` 有明确作品认可且写明范围。认可Skill优化方向、发布作品、程序通过、代理自评或阅读点赞均不能触发作品认可。后续否定应追加证据并更新状态/范围，不覆盖原反馈。局部认可不能升级为整篇或跨题材认可。

发布数据采用追加快照，保留用户相对时间原话；缺反馈日期或时区时不猜绝对日期。缺账号历史基线、曝光来源或相同观察窗口时，不归因于标题、内容、画风，也不据此自动调整偏好。

## 迭代验收

优先用相同真实输入对照旧版与新版，记录首次可用程度、用户实际要求的返工轮数和具体问题是否减少。指标未知就写待评，不能将脚本通过或AI自评冒充用户认可。选题贴近、形式贴近、内容原创独立审查；图文配合按 `qa-checklist.md` 逐卡核对。暂时只有规则更新时，如实报告“规则已落实，创作改善尚待真实任务验证”。

## 选题边界固定检查

见 `evals/topic-alignment.md`，覆盖贴近选题、主体任务漂移、空泛标题、仅换词、用户授权拓展和素材缺失。此类检查需要实际理解输入，不把关键词匹配或程序通过当作语义验证。本轮规则更新不证明新文章已经更贴近，仍需真实任务验证。

## 认可案例的积累

只在用户明确认可时，将相应项目中可复用的局部输入、输出、评价和认可证据整理为新案例，并注明 `status: user_approved` 和实际证据位置。只保存必要片段与泛化规则，不打包第三方原图或整篇原文。

用户不认可的内容只抽取通用失败规则，例如“并列卡不得无故转连续故事”“长解释不得压成标语”。已删除的失败作品不恢复、不作为正向样本。当前保留的项目未经明确认可，不能自动归入认可案例。
